# Project Rules (AI-Assisted Development Presentation Slides)

These are the rules and guidelines for the AI-Assisted Development presentation slides. They outline the approach, expectations, and constraints for creating and delivering the presentation.

1. There should be a file that lists all the slides with enabled/active status, so it is easy to enable or disable slides before the presentation. The slide number or order should reflect the intended sequence of the presentation. for instance, let's say we have 5 slides but right before the presentation we decide to disable slide 3, then when i ran the project, slide 3 should be skipped and the remaining slides should maintain their intended order. Include a visible slide counter and progress indicator.

2. it needs to have a presenter view or notes section, so the presenter can see additional context, cues, or reminders that are not visible to the audience. this helps the presenter stay on track and deliver the content effectively. it should also have timer. (just follow the standard practice for presenter view in presentation software.). don't overcomplicate it, but make sure the essential information is easily accessible to the presenter. i should be able to set notes for each slide that are visible only in the presenter view. I don't think a single browser window with the slides is sufficient for this purpose. i should be able to have a separate view for the presenter that includes notes and a timer.

3. The presentation should be visually clear and well-structured. Use consistent fonts, colors, and layouts to ensure readability and a professional appearance. Avoid cluttered slides and excessive text. Each slide should focus on a single idea or topic, with supporting visuals or bullet points as needed.

4. for animations, use them sparingly and purposefully. Animations should enhance understanding or draw attention to key points, rather than distract or overwhelm the audience. Avoid excessive or flashy animations that do not contribute to the content. try to add animated illustrations like undraw or here in https://meatproxy.me/. ( i have some of the svg here `/Users/bs01379/dev/presentation/how-we-use-ai-in-informatiq/src/assets/meatproxy-emojis-svg` ). also try to scrape animaitons from the meatproxy website if needed. don't just rely on meatproxy, if there are other sources of suitable animations, consider using them as well. don't overuse animations to the point where they become a distraction rather than a helpful visual aid. one slide should not have more than one or two (at best) animated illustrations.

5. Use a consistent 16:9 presentation ratio. Support fullscreen presentation mode. Ensure slides fit the viewport without unwanted scrolling.

6. Don't force every slide into cards, grids, or three-column layouts.

7. Prefer subtle entrance animations, staggered reveals, and coordinated transitions. Animate diagrams progressively to explain how a process works. Use animations to guide attention, not to entertain.

8. Make important concepts visually obvious without requiring the audience to read everything.

9. Use code snippets and terminal-style elements only when they add value.

10. Use visual storytelling to explain concepts such as AI orchestration, human involvement, context engineering, and AI-generated output.

11. Prefer diagrams, flowcharts, timelines, comparisons, and visual metaphors over text.
12. Make the presentation feel like a continuous story, not a collection of unrelated slides.
13. Use strong, thought-provoking headlines instead of generic titles.
14. Use generous whitespace. Don't overcrowd slides. Avoid generic PowerPoint-style templates.
